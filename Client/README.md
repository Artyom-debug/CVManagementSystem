# Forma — React-клиент CV Management System

## Запуск

Требуется Node.js 22.12+ (проверено на Node.js 24).

```powershell
cd Client
npm ci
npm run dev
```

Откройте http://127.0.0.1:5173. API запускается отдельно существующим способом. Серверные исходники не менялись.

Vite проксирует `/api` на `https://localhost:7240`, соответствующий HTTPS-профилю `Web/Properties/launchSettings.json`. Для другого адреса создайте `Client/.env.local`:

```dotenv
API_TARGET=https://localhost:7240
```

В production отдавайте `dist` как SPA (fallback на `index.html`) и проксируйте `/api` на ASP.NET с того же origin. `npm run preview` предназначен для просмотра сборки, а не production-хостинга. HTTPS-проверка отключена только у локального Vite proxy для сертификата разработки.

```powershell
npm run build
npm test
```

Проверки: 20 автоматических тестов покрывают очередь сохранения, конфликты версий,
обновление токенов, заполненность CV, ограничение запросов при прокрутке и обработку ошибок входа.
`test/browser-smoke.cjs` проверяет интерфейс в headless Edge с тестовыми API-ответами:
обе темы, подгрузку, конструкторы, автосохранение и мобильную ширину. Для него нужен
Playwright (путь к установленному модулю можно указать через `PLAYWRIGHT_MODULE`)
и запущенный `npm run dev`. Запуск: `node test/browser-smoke.cjs`.
Снимки сохраняются в игнорируемый каталог `.artifacts`; реальная база не используется.
Дополнительная проверка формы входа, логотипов провайдеров, уведомлений 4xx, страницы 500 и мобильной вёрстки:
`node test/auth-errors.cjs`. Переменная `CLIENT_URL` позволяет задать другой адрес Vite.

## Реализация

- React + TypeScript + Vite, Bootstrap, TanStack Query / Virtual, React Router.
- Монохромные тёмная и светлая темы; русская и английская локализация. Настройки сохраняются в localStorage.
- Таблицы позиций и атрибутов; в строках библиотеки доступны карандаш и корзина с проверкой роли.
- Для гостя `/positions/public`, кандидата `/positions/available`, рекрутёра и администратора `/positions/managed`.
- Виртуализированная бесконечная прокрутка: страницы по 30, один запрос одновременно, не чаще раза в 800 мс. При скорости > 4 px/ms данные заменяются размытыми скелетонами. После 220 мс покоя подгрузка продолжается. Непросмотренные страницы не загружаются заранее. Смена фильтра отменяет устаревший fetch; ошибка не вызывает бесконечных повторов.
- Конструкторы позиций и атрибутов, порядок полей, технологические теги, типизированные правила доступа, дублирование позиции, пакетное удаление атрибутов. Тип существующего атрибута неизменяем согласно API; удаление системных атрибутов доступно только администратору.
- Профиль: обязательные поля, дополнительные атрибуты, проекты, CV. Атрибуты автоматически сохраняются каждые 7 секунд; сохраняются только изменённые значения. Проекты имеют отдельную форму с явным сохранением.
- Все версии отправляются по контракту сервера. Очередь профиля передаёт новую версию следующему запросу, сохраняет более свежие правки во время запроса и останавливается при ошибке. Перезапись после конфликта автоматически не выполняется.
- Создание CV из позиции, редактирование значений с записью в профиль, публикация только заполненных CV, лайки, удаление CV. Кандидатам скрываются CV недоступных позиций на основании `/positions/available`.
- Markdown через react-markdown/remark-gfm без raw HTML. Теги с автодополнением через react-select. Drag-and-drop изображений через react-dropzone: подпись запрашивается у API, файл отправляется прямо во внешнее хранилище.
- Страница позиции: название, теги, описание, атрибуты, обсуждение и список CV для рекрутёров/администраторов. Обсуждение опрашивается раз в 4 секунды на открытой странице, без фонового polling. Авторы отображаются по email; ссылка на профиль доступна рекрутёрам и администраторам.
- `GET /api/positions/{positionId}/cvs?Page=1&PageSize=30` возвращает страницы CV: опубликованные для рекрутёра и также черновики для администратора, без удалённых CV. При отсутствии CV отображается `No CV`.
- Системные атрибуты автоматически входят во все CV, включая существующие. Чтение, редактирование и проверка публикации используют одну серверную выборку без дублей.
- Фото после загрузки сразу появляется в аватаре профиля; после перезагрузки используется подписанный URL сервера. Проекты и CV представлены карточками с горизонтальной прокруткой.
- JWT/refresh token хранятся в sessionStorage. Одновременные 401 объединяются в один refresh. Роли в UI не заменяют серверную авторизацию.
- Форма входа расположена по центру, кнопки Google и Facebook с логотипами — под email-формой. Ошибки 4xx показываются в закрываемом всплывающем уведомлении с текстом ответа API; содержимое выводится как текст, а не HTML. Форма остаётся открытой. 5xx ведут на `/errors/500`; технические подробности серверных сбоев скрыты. Пароли и текст серверной ошибки в навигацию не передаются.
- Добавление атрибута в профиль или шаблон CV открывает библиотеку в режиме выбора одного атрибута и возвращает обратно. Черновик позиции и проекта сохраняется в состоянии навигации. Системные атрибуты не редактируются; удаление системного атрибута доступно только администратору.
- Автосохранение пропускает незавершённые даты; остальные поля сохраняются. Очистка даты отправляет `null`, законченная дата — строку `YYYY-MM-DD`.

## Ограничения существующего API

Клиент не выдумывает отсутствующие endpoints и не подменяет данные демонстрационными.

1. `GET /positions/{id}` требует входа. Гостю доступно описание из строки публичного списка; при прямом переходе требуется вход.
2. Нет рейтинга top-5, количества кандидатов/рекрутёров, общего полнотекстового поиска. Верхний поиск фильтрует уже загруженные позиции и явно обозначает область поиска. Поиск атрибутов использует существующий `/attributes/search`, который возвращает весь результат без пагинации; обычная библиотека пагинируется.
3. Нет HTTP-контроллера управления пользователями. Экран администратора показывает это ограничение. Поиск по ID удалён; профили открываются по email из обсуждений и списков CV.
4. DTO чужого профиля не содержит `Version`; безопасное редактирование чужого профиля администратором невозможно. Доступен read-only экран и редактирование конкретного CV администратором, где версия профиля есть.
5. Если у автора обсуждения нет профиля кандидата, его email отображается без ссылки на профиль.
6. OAuth callback возвращает JSON, а не перенаправляет в SPA. Вход через popup поддержан, если callback обслуживается с того же origin, что и клиент. При отдельном origin API нужно настроить публичный origin/reverse proxy и redirect URI провайдера. Секреты Google/Facebook и подтверждение email настраиваются только на сервере.
7. Нет endpoint для системных атрибутов: мастер первоначального заполнения читает библиотеку постранично и получает детали системных полей. Нет endpoint пакетной проверки доступности CV: список CV сверяется с постраничной выдачей доступных позиций. Для больших объёмов потребуются соответствующие API.
8. CVDto в списке профиля не содержит числа лайков. Число отображается на странице CV, где оно есть в DTO.

## Структура

`src/lib/api.ts` — transport, ошибки и refresh; `types.ts` — DTO; `saveQueue.ts` — очередь оптимистического сохранения; `components/InfiniteTable.tsx` — виртуализация и регулирование подгрузки; `components/Fields.tsx` — движок типов, загрузка изображений и выбор атрибутов; `pages` — страницы и конструкторы; `styles.css` — адаптивные темы.
